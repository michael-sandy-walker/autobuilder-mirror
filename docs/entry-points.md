# Reading Autobuilder from its entry points

Start with [`AutobuilderApplication.main()`](../src/main/java/com/walpro/autobuilder/AutobuilderApplication.java#L14), then trace a single cycle from [`AutobuilderController.runSingleCycle()`](../src/main/java/com/walpro/autobuilder/controller/AutobuilderController.java#L278) to the first call to `agent.execute(context)`. That gives you the two paths you’ll come back to most often when reading the code.

## 1. Follow startup to a project run

1. **`AutobuilderApplication.main()` → `HomeApplication.launch()`.** The launcher reads the startup project choice. With no project configured, the home context waits for a choice on port 8080 by default. With a project supplied through `--file.base-path` or `FILE_BASE_PATH`, the launcher starts the project run during startup. [HomeApplication.java](../src/main/java/com/walpro/autobuilder/home/HomeApplication.java#L108) · [ProjectChoice.java](../src/main/java/com/walpro/autobuilder/home/ProjectChoice.java)
2. **Home screen → `POST /home/start`.** Follow this handler to see how the selected directory, mode, and profiles become a `ProjectChoice`. Both startup paths converge on `ProjectLauncher.start()`. [HomeController.java](../src/main/java/com/walpro/autobuilder/home/HomeController.java#L521) · [ProjectLauncher.java](../src/main/java/com/walpro/autobuilder/home/ProjectLauncher.java#L82)
3. **`ProjectLauncher.start()` → `bootRunContext()`.** The launcher starts a separate Spring context for the chosen project on port 8081 by default. From there, read `AutobuilderService.init()` and `runFirstCycle()` to see how startup initializes the run and decides whether to advance it. [ProjectLauncher.java](../src/main/java/com/walpro/autobuilder/home/ProjectLauncher.java#L127) · [AutobuilderService.java](../src/main/java/com/walpro/autobuilder/core/service/AutobuilderService.java#L681)

## 2. Follow a single cycle through three layers

| Read in this order | What to look for |
| --- | --- |
| [`AutobuilderController.runSingleCycle()`](../src/main/java/com/walpro/autobuilder/controller/AutobuilderController.java#L278) | `POST /autobuilder/cycle` calls the service and returns the current status. `POST /autobuilder/evolve` calls the same service method and returns a text response. |
| [`AutobuilderService.runAutobuilderCycle()`](../src/main/java/com/walpro/autobuilder/core/service/AutobuilderService.java#L951) | The scheduler and both endpoints share this entry point. Follow the lock into `runAutobuilderCycleLocked()`, then jump to [the call to `cycleExecutor.runCycle()`](../src/main/java/com/walpro/autobuilder/core/service/AutobuilderService.java#L1491). The service can return before running agents, including when scheduling is disabled or runtime context preparation fails. |
| [`CycleExecutor.runCycle()`](../src/main/java/com/walpro/autobuilder/core/lifecycle/CycleExecutor.java#L149) | The executor syncs the active goal and subgoal into the context and checks for early exits. After the engine returns, it handles follow-up work such as scope checks and persisting the evaluation result. |
| [`AdaptiveExecutionEngine.runCycle()`](../src/main/java/com/walpro/autobuilder/core/engine/AdaptiveExecutionEngine.java#L82) | The engine deliberates, filters roles by mode, orders the candidates, and checks each candidate’s eligibility before calling `execute()`. It can recheck a role after another agent updates the context. |

Keep [`CycleContextData`](../src/main/java/com/walpro/autobuilder/core/lifecycle/CycleContextData.java#L38) open while following the handoffs. Start with the active subgoal, the mutation outcome, and the state returned by each agent. For agent order, read the engine’s class comment and `selectionComparator()`. The current code compares explicit constraints, open-request urgency, participation-window boost, and base priority in that order, then uses pipeline order to break ties. The walk stops early on a merge or a halt condition. [AdaptiveExecutionEngine.java](../src/main/java/com/walpro/autobuilder/core/engine/AdaptiveExecutionEngine.java#L29)

## 3. Read one agent handoff end to end

Pick a cycle where evolution has an active subgoal. Read [`EvolutionAgent.execute()`](../src/main/java/com/walpro/autobuilder/agent/evolution/EvolutionAgent.java#L66) to see how it proposes a mutation. Open the [evolution protocol contract](../src/main/java/com/walpro/autobuilder/protocol/evolution/EvolutionProtocolContract.java) alongside it to see what goes into the model prompt. Next, follow [`EvaluationAgent.execute()`](../src/main/java/com/walpro/autobuilder/agent/evaluation/EvaluationAgent.java#L156) to see how the proposal gets a verdict, and [`MergeAgent.execute()`](../src/main/java/com/walpro/autobuilder/agent/merge/MergeAgent.java#L104) to see where eligible changes are applied.

If you’re tracing how a subgoal gets chosen or advanced, start with [`PlannerAgent`](../src/main/java/com/walpro/autobuilder/agent/planner/PlannerAgent.java) and [`GoalPlannerService`](../src/main/java/com/walpro/autobuilder/goal/GoalPlannerService.java). For small examples you can read without starting a project run, open [`ProjectLauncherTest`](../src/test/java/com/walpro/autobuilder/home/ProjectLauncherTest.java#L23) for startup behavior and [`AdaptiveExecutionEngineOrderingTest`](../src/test/java/com/walpro/autobuilder/core/engine/AdaptiveExecutionEngineOrderingTest.java#L111) for what stops the agent walk.

## 5. Use the map to answer a concrete question

### Why did a proposed change stay out of the project?

1. Start at [`EvolutionAgent`](../src/main/java/com/walpro/autobuilder/agent/evolution/EvolutionAgent.java) and find the call to `applyRegularMutations()`. Follow [`MutationApplier`](../src/main/java/com/walpro/autobuilder/core/service/MutationApplier.java) to see where the proposal is staged. Keep the cycle ID so you can match the proposal with later evidence.
2. In [`EvaluationAgent`](../src/main/java/com/walpro/autobuilder/agent/evaluation/EvaluationAgent.java), find `compileProbeService.probe(context)` and `heuristicNegotiator.negotiate(...)`. Inspect the build evidence alongside the resulting acceptance state. Follow [`EvaluationGraphFacade`](../src/main/java/com/walpro/autobuilder/graph/evaluation/EvaluationGraphFacade.java) if you need to locate the recorded evaluation.
3. In [`AdaptiveExecutionEngine`](../src/main/java/com/walpro/autobuilder/core/engine/AdaptiveExecutionEngine.java), check whether the merge role was allowed and eligible after evaluation. If it ran, follow [`MergeAgent`](../src/main/java/com/walpro/autobuilder/agent/merge/MergeAgent.java) into [`FileVariantCollector`](../src/main/java/com/walpro/autobuilder/core/service/merge/FileVariantCollector.java) and [`MergeProcessor`](../src/main/java/com/walpro/autobuilder/core/service/merge/MergeProcessor.java) to see which candidates were considered and what was applied.

### Why did a cycle work on this subgoal?

1. Start at [`CycleContextCoordinator`](../src/main/java/com/walpro/autobuilder/core/lifecycle/CycleContextCoordinator.java) and follow `prepareRuntimeContext()`. Compare the cycle’s current subgoal ID with the goal tree.
2. In [`GoalPlannerService`](../src/main/java/com/walpro/autobuilder/goal/GoalPlannerService.java), search for `applyGoalProgress` and `promoteCurrentSubGoal` to see how the prior outcome can advance the active subgoal. If the planner created work, start at [`PlannerAgent`](../src/main/java/com/walpro/autobuilder/agent/planner/PlannerAgent.java) and follow its protocol contract and response parser.
3. For a run you’re inspecting, use [`BehaviourLogger`](../src/main/java/com/walpro/autobuilder/observability/behaviour/BehaviourLogger.java) to find the event emitted at the decision point. Use the goal graph implementation when you need to see how the resulting goal state is stored.

### When an unfamiliar class appears

Use **Find Usages** on the method you’re reading to identify the layer that calls it. For an injected interface, use **Go to Implementation** and check [`AgentEngineConfig`](../src/main/java/com/walpro/autobuilder/config/AgentEngineConfig.java) or [`AppConfig`](../src/main/java/com/walpro/autobuilder/config/AppConfig.java) when several implementations are available. For a record or enum, start with a writer and a reader of the relevant field or value. That shows where the value is decided and which later behavior depends on it.
